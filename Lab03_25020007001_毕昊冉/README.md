需要 Windows、.NET 8 SDK，以及 Windows Forms 开发环境。也可以用安装了“.NET 桌面开发”工作负载、支持 .NET 8 的 Visual Studio 2022 打开 `Lab03desktop/Lab03.sln`

## 怎么操作

1. 打开程序后会自动开始一轮，初始范围是 `[20,80]`
2. 在“候选值”输入框中填一个整数，点击“提交”
3. 根据“需要调高”或“需要调低”的提示继续输入，历史区域会按先后顺序显示反馈
4. 猜中后会显示答案，再点“提交”会提示本轮已结束
5. 点击“开始新一轮”，程序会清空输入和历史，恢复初始范围并重新生成目标

## 主要代码在哪里

| 内容      | 字段或方法              | 作用                                        |
| ------- | ------------------ | ----------------------------------------- |
| 本轮目标    | `randomNum`        | 保存随机生成的整数                                 |
| 当前下界和上界 | `lownum`、`highnum` | 初始为 20、80，随比较结果更新                         |
| 结束标记    | `isFinished`       | 命中后设为 `true`，阻止继续提交                       |
| 历史数据    | `history`          | 用 `List<string>` 保存候选值、反馈和当前区间            |
| 候选值列表   | `guessHistory`     | 已声明并用于重复检查，但目前没有添加数据，检查尚未生效               |
| 提交处理    | `registe_Click`    | 检查输入、比较大小、更新区间及历史                         |
| 历史展示    | `RefreshHistory`   | 清空 ListBox，再用 `foreach` 遍历 `history` 添加记录 |
| 重新开始    | `RestartNew_Click` | 清空本轮数据、恢复区间、重新生成目标                        |

目标只在构造函数和“开始新一轮”事件中生成，提交事件不会重新抽取`Random.Next(20,81)` 的上限不包含 81，所以 20 和 80 都有机会出现

## 测试结果

已验证：非整数、空输入和当前有效区间外的数会被拒绝；目标为 20、80 时可以命中；命中后继续提交不会新增记录；重新开始会恢复区间、清空历史和输入

固定目标测试是在临时测试副本中将 `testmode` 设为 `true`、`testNum` 保持 `53` 后执行原有事件逻辑，弹窗改为收集提示文本，方便连续记录结果。手动复现时，在 `Form1.cs` 中设置上述常量并重新编译运行；边界测试将 `testNum` 分别改为 `20` 和 `80`。测试后恢复 `testmode = false` 并重新编译，正常演示使用随机目标

| 固定目标为 53 时的操作 | 实际结果                       |
| ------------- | -------------------------- |
| 输入 40         | 提示猜小，区间 `[41,80]`，1 条记录    |
| 输入 70         | 提示猜大，区间 `[41,69]`，2 条记录    |
| 再输入 40        | 拒绝，区间仍为 `[41,69]`，历史仍为 2 条 |
| 再输入 30        | 拒绝，区间仍为 `[41,69]`，历史仍为 2 条 |
| 输入 53         | 命中并结束，记录增加到 3 条            |
| 命中后输入 60      | 提示本轮已结束，区间不变，仍为 3 条记录      |
| 开始新一轮         | 区间恢复 `[20,80]`，记录和输入清空     |
